this repo reads it automatically before doing anything else.

## How to steer this file

The "Next step" and "Blockers / notes" sections below come from trailers on
your most recent commit message:

```bash
git commit -m "feat(x): short subject" -m "Next: wire up Y" -m "Blocked-by: waiting on API key from ops"
```

Omit a trailer and its section keeps whatever it already said — the hook never
invents a plan or a blocker, so nothing resets to empty just because a commit
didn't mention it. Use `Blocked-by: none` (or similar) to explicitly clear it.

## What happened last

**fix(context): use git's own trailer parser for the resume fields** _(2026-08-17, Gino Carrasco)_

The previous implementation regex-scanned the whole commit body for lines
starting with Next:/Blocked-by:/Blockers:, so ordinary prose that wrapped onto
a line beginning with one of those words was captured as if it were a trailer.
The very commit that introduced the feature hit this: its body explains the
trailer convention, and a wrapped line starting "Blockers:) on HEAD when
present..." became the Blockers value, and was also cut out of the summary.

Read %(trailers:only) instead, which only recognizes the contiguous key: value
run at the end of the message, and strip exactly those recognized lines off the
tail of the body rather than filtering by keyword anywhere in it.
